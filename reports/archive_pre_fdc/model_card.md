# Packr model card: success-rate and shelf-life surrogate (phase 5)

Generated by `python -m packr.ml.train` on 2026-10-26 (LightGBM 4.7.0). Numbers come from `reports/ml_metrics.json`.

## What this model is

A LightGBM surrogate of the Packr Monte Carlo simulator (`packr.sim.physics`). It predicts the simulated success rate (share of trials reaching the target shelf life with no hard failure) and the simulated shelf-life p10/p50/p90.
**Every simulator parameter is an assumption and the simulator is uncalibrated** (spec section 0). The figures below measure how well the model reproduces the simulator. They are **not** evidence about real packaging performance; that evidence is still almost absent (spec section 9.2). Every success rate shown to users is a *simulation-based estimate*.

## Inputs

* 22 plan-input and package features: `is_snack, moisture_pct, fat_pct, ph, resp_rate_mgco2_kg_h, log_target_days, temp_c, rh_pct, chilled, harsh, log_otr, log_wvtr, light_barrier, seal, strength, thickness_um, n_layers, breathable, mass_kg, area_m2_per_kg, log_perf, flush_o2_pct`.
* 14 commodity-profile features (spec 7.2): `base_life_days, q10_decay, o2_min_pct, co2_max_pct, crit_weight_loss_pct, ma_gain, transp_g_kg_d, crit_aw, iso_b, ox_ref_days, ea_ox_kj, light_sens, ideal_temp_c, fragility`. NaN where a parameter does not apply (snacks have no O2 floor, produce no critical aw).
* At prediction time the profile comes from the commodity table, user overrides, or the mean of the 3 nearest table commodities (`packr.profile`). The last case is flagged `profile_source = estimated`.

## Heads

* `success_rate`: `objective=cross_entropy` on the fractional label, monotone non-increasing in `log_target_days`. Fail rate = 1 - success.
* `shelf_life_p10`, `p50`, `p90`: three L2 regressors on log days (labels clipped at 0.05 d). Predictions are sorted so p10 <= p50 <= p90.
* Failure-mode breakdown is **not** predicted; the API takes it from a direct 1,000-trial simulator run (spec 7.4).

## Data and protocol

* Train: 85,100 rows (real + virtual commodities). Test: 11,000 rows from 11 held-out real commodities: Apple, Banana Chips, Cauliflower, Cream Biscuits, Cucumber, Lettuce, Mango, Okra, Potato, Roasted Peanuts, Strawberry.
* Split by commodity; virtual commodities come only from train commodities; CV folds are by parent commodity (spec section 5).
* Hyperparameters chosen by grouped 5-fold CV on train (grid of 12), scored on the real rows of each held-out fold. Success head: `{'num_leaves': 127, 'min_child_samples': 40, 'n_estimators': 800, 'learning_rate': 0.03}`. Shelf-life heads: `{'num_leaves': 127, 'min_child_samples': 40, 'n_estimators': 800, 'learning_rate': 0.03}`.
* The test file was scored once, after the parameters were frozen. Anchors were not used.

## Monotonicity check

Doubling WVTR on every snack test row moves the mean predicted snack success from 0.630 to 0.586 (passes: it must not rise).

## Limits

* Inherits every simulator limit (spec 4.3): no frozen storage, no ethylene, no microbial model, steady-state produce gas balance, linear snack isotherm, placeholder material values.
* Covers two categories only (fresh produce, dry snacks); category extrapolation fails (spec section 6).
* The training distribution is a sampling design, not real requests (spec 11.8). Temperatures outside 0 to 38 C, targets above 400 days, or packs far from the sampled geometry are extrapolation.
* The deliverable model is refit on all 48 commodities (`--final`); its test-set numbers are the ones above, from the held-out run.

Dataset: seed 0, 85,100 train / 11,000 test rows.
